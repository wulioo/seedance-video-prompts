# Seedance 视频提示词知识库

将用户的创意、图片、视频或分镜需求转成可以直接提交的提示词。学习相应版本官方指南的指令组织方式；只编写提示词，除非用户另行要求生成视频。

## 生成模式默认规则

按用户已确认的偏好，**新视频提示词默认采用全能参考（全模态参考）方式**，适用于Seedance 2.0和2.5。只有用户明确要求“用首尾帧模式”或等价的模式选择时，才输出对应首尾帧模式的提示词。同项工作已明确选定模式后，“继续／再来一版”沿用该模式；新任务回到全能参考。

- 分镜文件、官方案例或素材文件名写了“首帧／尾帧／首尾帧”，以及用户仅描述开场、结尾或关键帧的画面，不构成切换模式的指令。按全能参考编写这些画面要求，不自动选择`first_frame/last_frame`，也不默认额外交付首尾帧备选版。
- 没有上传素材时，按现有剧情和资产设定列建议参考素材及待上传映射；不冒称素材已存在或已看过，不因缺附件自动改成纯文生。只有关键素材身份不明才询问。
- 用户明确请求原视频编辑、延长、纯文生或其他模式时，遵循该具体任务；不要为套默认生成模式而改变已授权的任务。
- 这是用户的制作偏好，不是官方模型限制。严格首尾帧的参数知识保留，只在用户明确选择对应模式或询问能力时使用。

## 先确定版本，再读取资料

| 用户意图 | 选用版本 |
|---|---|
| 新任务未指定版本，或只说 Seedance / 即梦 / 视频提示词 | Seedance 2.0 |
| 明确要求 Seedance 2.5、seedance2.5、SD2.5，或在 Seedance 上下文说“用 2.5” | Seedance 2.5 |
| 同一个提示词的“继续”“再来一版”“按刚才规则” | 延续这项工作的已选版本 |
| 明确改回 2.0，或开始一个未指定版本的新主题 | Seedance 2.0 |
| 同时要求两个版本 | 分别读取、分别生成并标注版本 |

根据语义判断版本选择。“不要 2.5”“对比 2.5 后仍用 2.0”不触发 2.5；正文、引文、素材文件名中偶然出现版本号不构成模型选择。明确点名其他模型时，不把此默认规则用来覆盖用户要求。

- **2.0 路径**：读取 [官方写作知识·2.0](references/官方写作知识_Seedance2.0.md) 和 [标注提示词模板·2.0](references/标注提示词模板_Seedance2.0.md)。涉及运镜、音色、多图/分镜参考或文字时，加读[关联写作知识·2.0](references/关联写作知识_Seedance2.0.md)；成片排障时读[常见问题与案例·2.0](references/常见问题与案例_Seedance2.0.md)。不加载2.5写法。
- **2.5 路径**：读取 [官方写作知识·2.5](references/官方写作知识_Seedance2.5.md) 和 [标注提示词模板·2.5](references/标注提示词模板_Seedance2.5.md)。多素材、编辑、延长、关键帧、白模、长剧情或声音绑定时，加读[素材与任务编排·2.5](references/素材与任务编排_Seedance2.5.md)，内容来自主指南明确推荐、已核验的官方`sd25-pe`。主指南明确说主体/运动/音频/风格参考可沿用2.0附录，仅沿用这些参考维度，不移植2.0的时间控制、动作偏好、人数建议或平台上限。禁止用未核验的第三方材料补充模型规则。
- **参数与输入边界**：用户涉及实际设置、素材规格、首尾帧与全模态组合、任务类型冲突时，读[生成参数与素材限制](references/生成参数与素材限制.md)，按版本查对应API/教程。首尾帧角色和全模态参考不可混用；自然语言首尾参考不等于参数锁定。
- **2.5飞书补充**：官网链接的飞书指南已取得完整正文；涉及细化摄影、情绪转折、一键成片、无缝转场或跨语言延长方向时，读[飞书补充写法·2.5](references/飞书补充写法_Seedance2.5.md)。飞书与官网/API的参数冲突已记录，不把文档可读性误判成必须用户登录。
- **来源优先级**：参数/角色/输入上限以对应版本当前API和使用必读为准；写作以对应版本主指南明确规则为主，官方关联专题及技能补充具体流程，案例作示范。遇到冲突记录差异，不择一句当成保证；见[官方文档对齐清单](references/官方文档对齐清单.md)。读取外部技能是核对资料，不自动执行其安装、自升级或生成命令。
- 用户自己的题材、创意、对白、素材和审美选择是任务输入；官方来源要求约束的是模型写作依据，不是禁止创作新剧情。
- 需要查源或更新时读取 [来源与维护记录](references/来源与维护记录.md)。没有核实的能力不写成已支持；资料不足时说明具体缺口，不能用别的版本填补。

## 编写流程

1. 先按上面的生成模式默认规则识别任务。用户只给镜号时，查项目分镜的动作、关联资产和相邻镜头连续性；分镜中的旧生成模式不能覆盖用户默认全能参考的偏好，只有用户明确选用首尾帧模式才切换。区别“借用某视频的运镜创作新视频”和“修改这段原视频”。
2. 提取主体、场景、事件、风格、声音、时长与素材用途。仅缺少关键剧情或素材身份时提问；普通创意细节可直接补全。用户指定的动作强度、台词、字幕和风格不能被模板默认值覆盖。
3. 区分已上传素材、文档中已指定但待上传的素材、纯文本创作，按下节处理。参考素材不仅列在清单中，还要在正文明确绑定主体或用途；引用语法遵循当前版本资料。无法查看的素材不声称已经看过，可基于用户提供的描述标明待核对项。
   - Seedance 2.0 按官方“定义主体”执行：主体包括人物、道具和场景；明确素材中的对象并赋予唯一标签。官方推荐2–3项稳定静态特征；本技能按用户确认的精简约定，以足够辨认对象为准，不机械凑数。单一明确对象可用类别命名，同图有相似对象时补位置或区分特征，关键连续性细节按需强调。同一主体的多个素材统一绑定，不同主体分别定义。已定义后，每次涉及主体都使用同一标签；未定义的简单场景每次使用“主体名@图片N”。正文不要以“他／她／它”、临时同义称呼或省略主体替代标签；使用“裴照的右手”等明确动作归属。具体句式与例子见2.0知识页及模板，不将本条作为2.5规则。
4. 按当前版本官方案例的表达方式与模板组织。参考任务先绑定素材，再描述场景与连续动作；不要只模仿风格词而漏掉引用。简单单镜头优先用连贯短段，复杂剧情再使用分镜或该版本支持的时间轴。将制作编号、验收说明和非必要工程细节留在正文外，保留有叙事作用的机位与连续性要求。标注栏是本技能的整理结构，不是官方 API 字段或必须输入的协议。
   - 按用户确认的写作约定，景别描述同时点明拍摄主体或对象，优先写“忧怜的中近景”“访事簿的特写”；局部特写明确归属，多人镜头点明同框对象。语义清楚即可，不强制固定句式，也不将此约定称为各版本官方的硬性语法。2.0依据与示例见[景别与拍摄对象](references/官方写作知识_Seedance2.0.md#景别与拍摄对象)。
5. 检查指代一致、任务动词准确、事件有先后、声音对应说话人、文字需求无冲突、参考素材没有互相争夺同一属性。生成参数和提示词正文分开，不能声称写入提示词就能改变接口参数。

## 参考素材状态与交付

| 素材状态 | 处理方式 |
|---|---|
| 已上传，编号和内容明确 | 按实际上传顺序列出简短映射，正文用当前版本引用语法绑定素材及其用途，不重新安排已有编号。 |
| 项目或用户已指定素材，但尚未上传到生成端 | 给出“建议上传顺序（待上传）”，说明每项资产负责身份、衣装、场景、道具、运镜或声音中的哪些属性；按该顺序先交付条件明确的提示词，注明上传完成且编号一致后使用。不能声称已查看或已上传。 |
| 关键素材身份不明确或相互冲突 | 先查项目资料；仍无法判断时，仅询问影响绑定的缺口，继续整理已确定的剧情与素材。 |
| 默认全能参考，但尚无具体图片 | 从已确定剧情或资产设定提出必要的参考素材，明确为待准备/待上传，不假装已查看；只为含义明确的素材建立建议编号。 |
| 用户明确要求纯文生 | 用文字定义主体，不强加参考图要求，不编造编号。 |

资产代号不等于上传编号，也不证明图片已经制作完成。多个资产可能已包含在同一张图中，应按实际图片组织，不能机械地每个资产分配一张图。仅为撰写提示词且素材身份清楚时，不必等待上传才完成草案。

## 输出约定

默认先用一行注明 `适用模型：Seedance 2.0/2.5｜任务：……`，再给可复制的完整提示词代码块。不要默认给两套版本、双语翻译、长篇教程或重复的注释版。

- 用户要“标注版/模板/拆解”：使用相应模板的标注字段，说明字段作用；用户要成品：替换所有占位内容，移除解释与空栏目。
- 用户只要正文：直接给提示词，不加版本说明等外围内容。
- 成品排版按用户已确认偏好：开头每个素材引用及其用途单独一行，相邻素材行之间不插入空行；素材组与后续场景、动作、声音等段落之间可空一行。默认不添加“素材参考”“整体风格与约束”等栏目标题，单镜头用自然段，多镜头按需要写“镜头1、镜头2”。这是用户排版偏好，不是官方强制格式。
- 2.0 的 `【】` 用于要出现在画面中的字幕文字，不用作提示词的栏目标题。说明写作依据时区分官方规则、项目剧情和用户排版约定，不把原创提示词或自定排版称为官方原版模板。
- 参考任务给出简短的已上传映射或待上传清单，正文保留素材绑定。Seedance 2.0 使用 `@图片1`、`@视频1`、`@音频1` 等引用，并说明各素材的作用；2.5 的具体语法只按其版本资料执行。需要设置 `role/ratio/duration/output_format` 时，在代码块外给对应设置提示，且只给当前任务用到的参数。
- 请求超出当前指南确认范围时，先查同版本官方材料；无法核实时明确限制，不承诺通过堆提示词解决。
- 正常创作使用本地已核验知识，不必每次联网；用户要求最新规则、参数变动或知识库没有覆盖的能力时，再核实同版本官方资料。
- 用户要求全量对齐时，逐节检查两份主指南及其正文链接、HTML链接和代码中的官方发布入口；同文锚点去重，官方关联专题按引用范围下钻。记录每个链接的已读范围、适用版本、落入哪份知识页或未读原因。资料访问失败不等于已核验；不将无限扩展的付费、开通、SDK、存储和运维链接当作提示词写作必读，也不遗漏它们的边界记录。

## 交付前版本检查

- 默认版本是否为 2.0？2.5 是否来自用户的明确选择或同项工作的延续？
- 新视频是否默认全能参考？首尾帧模式是否来自用户明确选择，而非仅来自分镜文件、素材命名或开头/结尾描述？
- 是否只应用选中版本资料？模板是否被误称为官方原版？
- 是否保留分镜指定的参考素材工作流？已上传与待上传是否清楚区分，正文引用是否与素材编号、身份和用途一致？不能用长篇外观描述代替应有的素材绑定。
- 2.0是否为需要精准引用的人物、道具、场景定位对象并命名？逐句核对主体标签和肢体归属，是否出现代词替代、同物异名或多素材被误认成多主体？
- 每处景别是否明确拍谁或拍什么？局部特写的归属、多人镜头的同框对象是否清楚？
- 是否把素材上限、推荐数量、效果概率误写为保证？
- 是否把分镜当精确时间控制、把提示词参考当首尾帧参数控制？依据当前版本资料逐项核对。
- 是否保留用户的创作目标，删除空占位符和无关内容？
