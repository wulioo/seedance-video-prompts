# 交付门禁

准备交付完整提示词、重写现有提示词或根据生成结果排障时读取。仅回答概念、查资料或说明功能而不交付提示词时无需加载。

本门禁使用统一的“镜头合同”覆盖不同题材、主体、动作、素材和生成模式，不按单个失败案例累积专用禁令。检查在内部完成，不默认向用户展示过程。

## 双层交付门禁

完整提示词必须同时通过两层检查，任何一层失败都不得作为正式提示词交付：

1. **语义镜头合同。** 使用下方镜头合同核对素材职责、剧情、主体、构图、空间、时间、声音和版本规则。这些内容依赖真实分镜与素材语义，不能由正则脚本替代。
2. **可执行校验器。** 对准备交付的最终正文运行 `scripts/validate_prompt.py --strict`，稳定拦截聊天外依赖、含糊续接、重复指令、元说明、未完成占位符、标签符号错误，以及 Seedance 2.0 明确字段中的声音／文字漏标。

从 Skill 目录执行文件校验：

```bash
uv run python scripts/validate_prompt.py --version 2.0 --task new --strict /path/to/prompt.txt
```

也可从标准输入校验：

```bash
uv run python scripts/validate_prompt.py --version 2.0 --task new --strict -
```

- `--version` 使用本次实际版本：`2.0` 或 `2.5`。
- `--task` 使用已确认的任务类型：`new`、`edit`、`extend` 或 `bridge`；仅在诊断未知文本时使用默认的 `auto` 推断。
- `--strict` 是完整提示词交付的必选项，使警告也能阻断交付；概念分析或中间草稿可按需省略。
- `--json` 可供自动化流程读取结构化结果。
- 退出码 `0` 表示可执行层通过，`1` 表示正文存在阻断问题，`2` 表示输入或命令错误。只有实际运行且退出码为 `0`，才能声称可执行门禁通过。
- 修订任何正文后都必须重新运行。Skill 结构校验 `quick_validate.py` 不能替代提示词校验器。

校验器采用通用语言与任务结构，不包含当前项目专用的主体、道具或剧情词，也不设置固定字数。脚本通过只表示没有命中可机械判定的问题；仍须完成语义镜头合同，且不等于保证模型生成结果。

## 镜头合同

写正文前，先为当前任务建立下表。每个适用维度只能是“已确认／不适用／待确定”；存在“待确定”时不得交付完整提示词。

| 维度 | 必须确认的内容 | 不通过情形 |
|---|---|---|
| 任务定义 | Seedance版本、生成／编辑／延长、全能参考或其他模式、镜头数量、目标时长 | 版本、模式或任务动词混用；把提示词控制冒充实际参数设置 |
| 权威来源 | 用户当前要求、分镜、剧本及每份素材分别控制哪些属性 | 同一属性由互相冲突的来源共同控制；未查看素材却据此下结论 |
| 核心叙事 | 本镜核心事件、变化节点、叙事结果以及与前后镜的必要衔接 | 只描述氛围，没有完整事件；模板或修复要求改写了剧情目的 |
| 信息密度与焦点 | 核心事件能够用一句话概括；每项细节提供唯一且必要的控制信息；辅助动作、氛围和限制的描述密度低于核心事件 | 把门禁检查项或修复解释写进正文；同一要求重复出现；辅助动作、微表情、负面限制或技术说明比核心事件更详细，导致模型存在多个注意中心 |
| 主体清单 | 每个主体的唯一身份、数量、所属素材、起始状态和结束状态 | 主体身份或数量含混；多视图误生多人；局部动作归属不清 |
| 变化合同 | 哪些属性必须变化，哪些必须保持，允许变化到什么程度 | 用“保持一致／发生变化”但未说明范围；修改一个属性时连带改动其他属性 |
| 可见性层级 | 每个画面元素属于核心主体、辅助主体还是连续性背景；分别要求完整可见、局部可见或允许出画 | 次要元素抢占核心主体；未经要求把已保留元素完全删除；需要验收的证据被遮挡或裁掉 |
| 摄影与构图 | 拍摄对象、景别、机位、角度、运动、画面占比、遮挡关系及起止构图 | 景别未点明对象；机位与可见面冲突；多个构图目标无法同框；参考图宽景无意覆盖目标近景 |
| 环境与空间 | 场景锚点、结构、道具、相对位置、接触面、路径、方向及允许改变范围 | 主体悬空、穿越障碍、走错路径；固定建筑或道具被旧文字静默改造 |
| 时间与顺序 | 开场状态、事件顺序、关键停留、对白、转场和结束状态能否放入目标时长 | 依赖未说明的跳切、瞬移或异常加速；关键事件、对白或反应时间不足 |
| 声音与文字 | 声源、说话者、出现时机、持续范围、字幕／画面文字及版本标注 | 声音归属不明；声画节点不对应；遗漏标签；禁止字幕与要求字幕同时出现 |
| 约束与输出 | 必须出现、必须保持、允许变化、禁止出现四类要求均有正文承载 | 负面词抵消正向目标；旧补丁残留；空占位、无关字段或无法独立执行的外部依赖 |

## 通用判定原则

1. **来源按属性分配，不按文件整体覆盖。** 用户当前明确要求决定创作目标；分镜负责本镜事件、动作顺序、摄影、声音和时长；剧本补充动机、对白及未写明内容；参考素材只控制被分配的外观、环境、构图、动作或声音属性。同一属性出现冲突时，先确认权威来源，不静默拼接。
2. **场景美术参考与构图参考分离。** 场景美术／空间参考只继承结构、材质、光色、道具形制和空间关系，不自动继承原图的景别、机位、前景主体、裁切或画面左右。只有被明确指定为本镜构图参考的素材才锁定原图构图。目标镜头不同，应在正文说明继承范围和不继承原图构图。
3. **构图服从可见性层级。** 核心主体获得主要画幅和清晰度；辅助主体必须可辨但不得遮挡或压过核心主体；仅作连续性的背景可以局部出现或出画。用户调整“重点、占比、远近、显著性”时，只改变层级或程度，不自动增加或删除主体。
4. **动作形成闭环。** 核心动作必须具备可识别的主体、目标、起始状态、过程和结束状态。位置、方向、接触、遮挡、先后或相对关系影响事件时必须写清；与核心事件无关的空间信息不强制塞入画面。
5. **变化范围必须封闭。** 对身份、面容、服装、道具、场景、光线、镜头、声音等变化，明确变化对象和保持不变的相邻属性，防止局部修改扩散为换人、换景、换装或换机位。
6. **正向目标优先。** 先写清需要生成的画面、动作和声音，再针对真实高风险补充少量限制。不得用大量“不出现／不要／禁止”替代目标构图，也不得让限制词删除叙事所需元素。
7. **信息密度服从叙事优先级。** 核心事件获得最多且最直接的描述；辅助动作只保留支撑核心事件所需的起始、过程和结果，不逐部位展开无关微动作。门禁检查、验收理由、修复过程和素材分析留在内部，不复制到提示词正文。同一控制要求只保留一次最清楚的表达；不设置固定字数，但删除任何一句后若不损失唯一控制信息，该句应当删除。
8. **唯一解释。** 核心主体、目标物、变化对象、机位、方向、时间顺序和声音归属必须各有唯一指向。仍存在两种以上合理执行方式时，先根据已提供资料消除；影响剧情或素材身份且无法判断时询问用户。
9. **声画服从版本资料。** 声音和文字只按任务需要加入。Seedance 2.0 中，背景音乐或持续声场用`（……）`，动作音效用`<……>`，对白用`{……}`，画面字幕用`【……】`；其他版本按其对应资料处理。

## 修订与排障

1. 实际查看用户提供的截图、视频或音频，先写“已见事实”，再写“原因推断”。单帧不能证明整段运动、声音或逐帧稳定。
2. 将偏差定位到镜头合同中的具体维度，只修改该维度及与它直接冲突的条件；用户未否定且仍相容的主体、关系、构图信息和连续性全部保留。
3. 占比、显著性、数量、速度或持续时间过高／过低时先调整程度，不从“太多”直接改成“完全没有”，也不从“不足”扩大成新的主体或事件。
4. 修订后重新生成一份自洽正文，删除被替代的旧条件，不把多轮反馈堆成互相竞争的补丁和否定词清单。
5. 已有生成偏差时启用增强模式，但只增加解决当前偏差所需的素材职责、构图关系、时间节点或声音归属。
6. 同类偏差重复出现时，检查参考素材是否强烈引导错误构图，必要时建议补充构图参考、落位图或后期合成；不能承诺仅靠提示词保证模型精确执行。

## 交付判定

交付前逐项复核镜头合同：

- 全部适用维度为“已确认”，其余为“不适用”。
- 每项关键要求都能在提示词正文中找到对应句子，且没有互相抵消的指令。
- 核心事件能够被目标镜头看见，辅助信息没有抢占主体，连续性信息没有被无故删除。
- 正文能够用一句话指出唯一核心事件；辅助动作、氛围、负面限制和技术说明没有形成第二注意中心，也没有把门禁检查或修复解释写进正文。
- 同一控制要求只出现一次最清楚的表达；不存在删除后不损失唯一控制信息的重复句子。
- 本次输入足以独立执行；素材编号、上传状态和职责表达真实，无假编号、空占位或聊天外依赖。
- 动作量、对白和声音节点能够容纳在时长内，声音及文字使用对应版本的写法。
- 修订任务只改动已确认的问题范围，没有过度修正或无关扩张。

任一适用维度仍为“待确定”、缺少正文证据或存在冲突时，先修订；关键缺口无法解决时只说明具体缺口并询问，不把草稿作为完整提示词交付。通过门禁不等于保证生成结果，成片仍以实际画面和声音核验。
